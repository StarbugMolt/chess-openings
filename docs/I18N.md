# English, French and Spanish

The header language button is available to signed-in and signed-out users. On a first visit, the app selects the first supported entry in `navigator.languages`; regional tags such as `fr-CA` and `es-MX` resolve to French and Spanish. If none is supported, it uses English. An explicit selection is saved under `chess-openings.language` in local storage and takes precedence on subsequent visits in the same browser. This preference is independent of the account and is not synced between devices. Storage failures leave detection and the current page's selection usable.

Switching languages updates the current screen, document `lang`, page title, accessible labels, feedback, teaching notes and date/number formatting. It does not remount a trainer, replay a move, reveal hidden variation names, fetch a new lesson, or modify a lesson's revision or private practice evidence. The button supports keyboard focus, Escape and outside-click dismissal. Navigation wraps for longer translations.

## Text ownership

`frontend/src/i18n/ui.json` contains interface translations, including known public API success/error messages. `lessons.json` contains the current ten courses' introductions, 25 lines' titles/descriptions, and their authored hints and explanations, plus retained course/line titles used by earlier practice history. Both catalogues use exact English source strings as keys with French and Spanish values. English is the source language and fallback. A changed or future source string therefore displays its original text until deliberately translated; an old translation cannot silently be applied to revised teaching copy.

Translations are presentation data in Git. No schema, importer, curriculum migration, authored chess path or lesson revision changes are needed. The backend continues to return the original course payload, and assessments continue to reference the same stable lesson/revision/line/colour and UCI paths. SAN/PGN, coordinates, ECO codes, imported Lichess names and the reference's search values retain their source spelling. Translated family buttons still search the original upstream name. Account JSON exports keep their stable machine-readable field names and original saved content.

Use `t(source, values)` at rendering time. Keep existing feedback as a string or a `message(source, values)` descriptor rather than storing a rendered translation, so changing language updates feedback already on screen. Whole interpolated sentences have reorderable placeholders. `joinText` retains individually translatable lesson titles inside an announcement. Vue text interpolation escapes content; no translated HTML or external translation service is used.

When adding UI or curriculum copy, add both translations with the same placeholders. The frontend unit checks validate catalogue entries and static translation calls. The disposable lesson integration checks every current course introduction, line title/description and step hint/explanation against both catalogues. New untranslated current teaching copy fails that check.

## Account emails

Account mutations send the selected language in `Accept-Language`. Symfony negotiates one of `en`, `fr` and `es` for verification, password reset and existing-account registration notices. `AccountEmailText` owns the translated subjects and bodies. English remains the default for existing API clients. Locale is request-scoped; no account column or additional personal data is stored.

French and Spanish verification/reset links carry `?lang=fr` or `?lang=es`, so another browser can display the email's language. Only supported values are accepted. The single-use token stays in `#token=…`, is removed from browser history as before, and retains its password binding and expiry. Language changes and token URL cleanup are watched independently, so removing a fragment cannot erase the in-memory token.
